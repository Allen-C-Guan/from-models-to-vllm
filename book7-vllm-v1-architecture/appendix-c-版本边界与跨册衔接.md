# 附录 C 版本边界与跨册衔接

## C.1 三种版本标签分别回答什么

| 标签 | 本书采用的观察点 | 用途与限制 |
|---|---|---|
| vLLM 阅读锚 | v0.30.0，`ced6857afa0ea7b2e3f0846a62e1394e90f15607` | 本书主要实现事实与源码导航；不等于工作区运行包 |
| Ascend 源码观察点 | `3b31886237ed65c435e0965b10e8002ff5769766` | 平台、Worker、Attention 与图封装的定向阅读；不宣称等于已装插件 |
| 历史运行基线 | vLLM 0.27.1、vllm-ascend 0.27.1rc1、torch／torch-npu 2.10 系列、CANN 9.1.0 | 旧实验的环境背景；本次重写未复测设备或运行包 |

这三行不是一份可直接安装的兼容清单。主锚和插件观察点支持各自代码中的职责解释；要真正运行某组版本，还需按相应官方兼容矩阵与环境记录验证。

本书中新请求、预算、块号、容量单位和张量小形状均为教学构造。没有把这些数字写成模型分词结果或吞吐实测。旧实验资产进入选读附录时，也没有把旧读数迁移为新版默认表现。

## C.2 对后续版本做了哪些检查

2026-11-02 的首轮调研复核了官方 v0.31.0、v0.32.0 发布说明，并保存 v0.32.0 的前端、核心、调度、KV 与两代 Runner 共八个文件，进行结构和样稿相关路径的定向对照。此次选择继续冻结 v0.30.0，没有升级环境，也没有声称对后续版本做过全量语义审计。

| 已发现变化 | 证据 | 阅读时怎样处理 |
|---|---|---|
| v0.31 等待队列与活跃请求约束变化 | [v0.31 发布说明](https://github.com/vllm-project/vllm/releases/tag/v0.31.0)，Scheduler 项 | 不把本书简化状态图当作以后版本的完整容器清单 |
| MRV2 功能与平台默认路径继续变化 | 两版发布说明及下载的 Runner 文件 | 先确认平台实际选择，再看对应 Runner |
| v0.32 调整上下文长度／max_tokens 处理 | [v0.32 发布说明](https://github.com/vllm-project/vllm/releases/tag/v0.32.0)，Breaking changes | 输入约束的架构责任不变，具体校验规则需重查 |
| v0.32 移除部分编译优化与 cascade attention | 同版发布说明对应变更 | 不将旧实现或旧配置直接视为新版本可用项 |
| v0.32 仍存在两代 Runner 相关文件 | 研究中保存的实际源码 | 不沿用旧规划里“预计移除”的说法；文件存在也不证明默认启用 |

官方设计文档也有自己的时间范围。V1 alpha 博客解释历史动机；Anatomy of vLLM 基于更早源码快照；多进程文档含 V0 和早期 V1 描述；Hybrid KV 文档明确标注历史提交。它们帮助理解设计，当前实现行为仍回到本书固定源码锚核查。

当未来版本改变类名时，可以先用本书的责任问题定位，再更新导航；当协议或状态语义改变时，则需要重新核验相关论述。前者是入口变化，后者可能影响理解，不能混为一次机械的链接替换。
