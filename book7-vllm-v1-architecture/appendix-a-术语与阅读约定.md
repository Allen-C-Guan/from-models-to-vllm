# 附录 A 术语与阅读约定

本书面向理解基本模型架构并读过 Book6 的读者，不要求先掌握 vLLM 类名或做过注册项目。阅读时先理解中文责任，再把英文名称作为源码检索线索。下面的术语按问题分组，而不是按字母排列。

## A.1 职责与运行位置

| 术语 | 本书中的含义 | 不应混淆的对象 |
|---|---|---|
| 前端 Front end | 面向调用者的输入、输出及核心客户端协调范围 | 不专指浏览器界面，也不只指一个类 |
| 引擎核心 EngineCore | 协调请求计算生命周期的核心 | 不是模型前向本身 |
| 调度器 Scheduler | 结合进度和资源形成当步计算安排 | 不等于副本间请求路由 |
| 执行器 Executor | 组织执行单元调用与结果交接 | 不等于某个设备算子 |
| 工作单元 Worker | 承担设备初始化与执行相关责任 | 类实例不总与进程一一对应 |
| 模型运行器 Model Runner | 请求状态到当步模型输入及结果的转换 | 不是模型结构定义的同义词 |
| 模块 Module | 代码组织单位 | 模块数不能推导进程数 |
| 进程 Process | 独立运行实例与地址空间 | 不等于设备；一个进程可控制设备 |
| 线程 Thread | 进程内共享地址空间的执行活动 | 共享内存并不免除同步责任 |
| IPC | 进程之间交换信息的机制 | 普通请求消息不等于复制全部模型／KV |
| 接口 Interface | 两方约定的输入、输出、约束与行为 | 不限于 HTTP API 或抽象基类 |
| 后端 Backend | 满足某种计算语义的具体实现 | 不能忽略 dtype、布局与能力约束 |

## A.2 请求、状态与执行

| 术语 | 本书中的含义 | 对应阅读 |
|---|---|---|
| 请求 Request | 一项带身份、输入和生成要求的工作 | 第 2、3 章 |
| 预填充 Prefill | 处理提示词并建立后续生成所需状态 | 第 1、5 章 |
| 解码 Decode | 利用已有历史继续生成 | 第 1、5 章 |
| 当步输入 token | 本轮真正送入模型处理的 token | 不等于本轮新输出数量；第 5、7 章 |
| 调度计划 Scheduler output | 本步成员、推进量及状态变化等安排 | 不是已经完成的结果；第 5、7 章 |
| KV cache | 保存注意力历史 K、V 等相关数据的状态设施 | 本书分管理信息和设备数据讨论；第 6 章 |
| 逻辑块／物理块 | 按请求顺序组织的块／资源池中的分配位置 | 两者经块表关联；第 6 章 |
| 引用 Reference | 某请求仍依赖一份资源的使用关系 | 引用释放不等于擦除内容 |
| 前缀缓存 Prefix cache | 复用相同计算前缀的已存状态 | 不是回答文本缓存 |
| 抢占 Preemption | 为资源周转暂停请求，使其之后有机会恢复 | 与取消终止不同 |
| 持久状态 Persistent state | 跨若干执行轮保存的信息 | 不表示落盘或故障恢复能力 |
| 元数据 Metadata | 说明张量归属、长度、位置和访问方式的信息 | 本身不替代张量数值 |
| 在途 In flight | 已提交但尚未完成相关消费／清理的工作 | 提交返回不等于数据可覆盖 |

## A.3 执行与扩展

| 术语 | 核心区别 | 对应阅读 |
|---|---|---|
| 阻塞／非阻塞 | 当前调用是否等待结果后才返回控制 | 第 2 章 |
| 并发 Concurrency | 多项工作在同一时间范围内推进 | 不保证同一瞬间并行执行 |
| 流式 Streaming | 用户是否分多次收到结果 | 不保证每个 token 一个网络块 |
| 编译 Compilation | 转换并优化计算实现 | 第 9 章 |
| 图捕获／重放 | 准备并复用可支持的设备执行组织 | 不等于所有形状都能复用 |
| 副本 Replica | 可协同完成模型推理的一套资源 | 一份副本可跨多卡 |
| TP／PP | 同一副本内的层内分工／阶段分工 | 第 10 章 |
| DP | 多副本处理不同请求集合 | MoE 专家通信可能使 rank 不完全独立 |
| Rank | 通信组参与者的逻辑编号 | 不总等于物理卡编号 |
| 投机 Speculation | 先提议候选，再验证并提交结果 | 第 11 章，Book8 第 2 章 |
| 结构化输出 | 让生成过程遵守语法或模式约束 | 第 11 章，Book8 第 3 章 |
| PD 分离 | 同一请求的 prefill、decode 跨实例接续 | 需要状态交接，不仅是请求路由 |

## A.4 图的读法与符号

蓝色是输入与交付，橙色是核心协调与调度，绿色是状态管理，紫色是执行。灰色通常表示上下文或未展开部分。第 3–12 章图顶部的小索引复用同一职责顺序，高亮表示该图关注范围。

职责框表示工作分工，部署容器表示进程或设备，状态图框表示生命周期状态；以具体图注为准。实线箭头按标签表示调用、消息、数据或阶段推进，虚线用于图注明确说明的映射／影响关系。时序图纵向和时间线横向只表示顺序，不把距离当作测得耗时。

T 表示当前计算中输入 token 总数，R 表示当前讨论的请求或采样行数，H 表示隐藏维，V 表示词表维，Hkv 表示 KV 头数，D 表示头维，N 表示块数，P 表示每块 token 数。它们在各图首次使用处均有具体范围；R 在投机或部分 prefill 中不必等于全部参与请求数。

构造例不宣称真实分词或默认调度轨迹；源码事实不等于本机硬件实测。精确版本区别见附录 C。
