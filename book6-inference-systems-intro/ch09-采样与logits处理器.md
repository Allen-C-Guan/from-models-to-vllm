# 第 9 章 采样与 logits processors：从分布到 token

> **最小背景栏**：temperature 与 top-k 的直觉你在 Book2 第 11 章 11.3 节已经见过（「只借方法不深讲——解码策略的系统拆解归推理册」），本章就是那句承诺的兑现：指回之后系统化。softmax 定义（Book1 第 2 章）与多项式采样的常识是全部前置。

## 9.1 一笔 2017 年的旧账

Book1 第 8 章讲原论文的 beam search 与长度惩罚时，章末欠账框里写着：长度惩罚的账与「借尸还魂」的去处都在本册——F8 的两半：主落点（penalties 全家福）在本章，另一半（「一次验证多条候选」的 beam 思想在投机解码还魂）在第 10 章。先把主落点还清。

采样的位置感先立住：它在 logits 与 token 之间——模型每步吐出的是全体词表上的打分（207M 是 32000 维），**把它变成下一个 token 的那一步**就是采样层。这一层不碰任何权重、不花任何带宽（相对而言），引擎的性能数字与它无关——但产品的手感（稳定与灵动的分寸）全由它定。它是引擎的「出口关税」：算得再快，出口这一刀决定你拿到什么。

## 9.2 temperature：分布的音量旋钮

logits 除以 $T$ 再 softmax：$T{=}1$ 原样、$T \to 0$ 分布坍缩为贪心（argmax）、$T$ 变大分布摊平。**例 9.1（构造例：5 token 分布的三温度手算）**：设 softmax 前 logits $[2, 1, 0, -1, -2]$。$T{=}1$：概率约 $[0.42, 0.23, 0.11, 0.06, 0.03]$（加占位符的其余）；$T{=}0.5$（logits 翻倍）：头部概率升到约 0.65——**更笃定**；$T{=}2$：头部降到约 0.31——**更随和**。手算要点：温度乘在指数上，头部与尾部的比按 $e^{\Delta/T}$ 缩放——分布的「形状」被拉伸或压扁，但**排序不变**（温度不改变谁第一，只改变第一名赢多少）。

温度与下一章投机解码还有一个伏笔连接：验证器的修正采样对温度同样敏感——**投机与温度不是简单叠加**，draft 在低温下更容易命中（分布尖）、高温下命中崩（分布平）——生产系统的联动调参是真实工程问题（Book8 第 2 章地界）。

实用口径三条：代码与数学要 $T{=}0$（贪心，可复现）；创作要 $T{=}0.7{-}1.0$（多样但不散架）；「幻觉变多」往往不是温度的锅——分布本身没有的确定性，温度拧不出来。

## 9.3 top-k 与 top-p：截断的两种哲学

temperature 还有一个工程暗礁：**T=0 与贪心的等价性**。多数实现里 temperature=0 会走 argmax 快路（完全确定性），但浮点上 T 趋 0 的极限路径偶尔与 argmax 有别（除以极小数的数值噪声）——复现性要求高的场景要显式用 greedy 路径而不是把 T 拧到零。细节，但排障时省一小时。

采样长尾是浪费也是风险——第 5000 名的 token 概率十万分之一，采到它多半是语病。截断两法：

**top-k**：固定保留前 $k$ 个（个数截断）。简单、可控，但对分布形状不敏感——分布很尖时保留 50 个是浪费（前 3 个已占 95%），分布很平时保留 50 个可能还不够。

**top-p（核采样）**：按**累积概率** $p$ 截断——从大到小累加到 $p$ 为止（自适应截断）。分布尖时自动只留几个、分布平时自动多留——「核」（nucleus）指被保留的那一小撮。

**例 9.2（构造例：两种截断的分歧）**：尖分布（一个 token 占 90%）：top-k=5 留 5 个（其中 4 个基本没机会）；top-p=0.9 留 1-2 个。平分布（50 个 token 各占 2%）：top-k=5 留 5 个；top-p=0.9 要留 45 个。**分歧的本质：个数是分布无关的、概率是分布相关的**——核采样把「留多少」交给模型当前的自信度。

## 9.4 penalties 全家福：与已生成内容的对账

这层还有一笔「隐藏税率」常被忽略：**统计与采样的每一项都在词表维（32000）上做逐元素操作**——在 decode 的微秒级预算里，softmax+截断+罚金+采样的合计不是零头（工程里 logits 管线能占 decode 步的百分之几）——「出口关税」不只是比喻，是真实税率。

三件罚金都改 logits（降低已出现 token 的分数），记账方式不同：三件的记法用一张小账最清楚（设 token v 已出现 c 次、罚金系数 w）：repetition 记的是**布尔账**（出现过就罚 w——管「说过没有」）；frequency 记的是**计数账**（罚 w·c——管「说了几遍」，复读机克星）；presence 也是布尔账但实现常与 repetition 的乘式不同（减式对乘式）。选型口诀：**怕复读用 frequency、怕回避用 presence、粗暴防重用 repetition**。

**repetition penalty**——出现过的 token 一律扣固定分（乘式或减式，实现各异）；**frequency penalty**——按出现**次数**线性扣（出现 3 次扣 3 份）；**presence penalty**——出现过就扣固定分、不管次数（管「说不说」不管「说几遍」）。工程直觉：复读机用 frequency、话题回避用 presence、粗暴防重用 repetition。

然后是旧账主角——**长度惩罚**。beam search 时代（Book1 第 8 章）的公式 $\mathrm{score} = \frac{1}{Y^\alpha}\sum_t \log p(y_t)$（GNMT 的 eq (14) 血统）：长候选的逐 token 概率连乘天然吃亏（越乘越小），除以 $Y^\alpha$ 打折补偿——$\alpha$ 就是「长度偏见的汇率」。当年它是 beam 的账，如今自回归采样场景下逐 token 出、没有「整句比大小」，长度惩罚退居 beam 类场景（本册第 10 章的验证框架是它的新亲戚）；但「概率账必须按长度校准」的思想，在第 10 章的期望接受长度里会再见面。

## 9.5 管线与顺序

管线还有一个容易被忽视的成员：**序列级约束**（禁用词表、结构化合法 token 掩码等）也以 logits processor 的形态插在管线里（把非法位置改负无穷）——它们与统计类 processor 同吃一个接口，这是「管线」设计真正的复利。结构化输出的完整故事（语法约束怎么高效编译）是 Book8 第 3 章的地界，本册点名即可。工程实现里这些操作排成**管线**（logits processors）：penalties 改分数 → 截断（top-k/top-p）→ 温度 → 采样。顺序是**有语义的**：温度与 top-k 可交换（线性缩放不改变 top-k 集合——`samplers.py` 的顺序实验代码化了这一点），但温度与 top-p **不可交换**——温度改变分布形状、核采样恰恰依赖分布形状。先升温再核采与先核采再升温，留下的 token 集合可以不同。不同引擎的管线顺序以各自文档为准（黑盒纪律）——本册教的是「顺序是分布形状的函数」这个原理，不是某家的排列。

实物 9.1 给出 `samplers.py` 的顺序实验读数（出处：本机实测，`log/book6-ch09/samplers_base.json`）：同一组 logits 上「温度→top-p」与「top-p→温度」两序的保留集与概率读数并列——顺序差异可见、可复算。

## 9.6 本章小结

F8 的主落点还清：三把尺（温度调形状、截断防长尾、罚金对旧账）+ 一个管线原理（顺序是分布形状的函数）。带走的心智：**采样层是「分布到序列」的接口——它决定产品的手感而非引擎的速度；一切采样的分歧最终都是对同一个问题的回答：你想要稳定还是惊喜**。下一章是本册的高潮章之一：把「先猜后验」变成机制，自回归串行这笔 2017 年的欠账交货。
