# Book7《vLLM V1 源码剖析（上）：引擎主链路》

> 《从模型到 vLLM》丛书第 7 册 · 前置：Book6《推理系统导论：从自回归数学到服务算法》（四版 mini 引擎与推理物理学全家；B6 系五钩 B6-1/3/4/6/9 在本册销项）。锚声明：源码阅读锚 = vLLM v0.30.0（commit ced6857，2026-09-22 tag，+0800 口径）；实验运行栈 = vllm 0.27.1 + vllm-ascend 0.27.1rc1（Atlas 910B3，CANN 9.1.0，全 NPU 主线）；两轨不混引、可互证。论文锚：arXiv 2309.06180（vLLM/PagedAttention）、2312.07104（SGLang）、2401.09670（DistServe）、2501.01005（FlashInfer）。Book8 领土（投机深讲/结构化输出/多模态与 LoRA 服务/PD 分离工程/可观测生态）为本册禁词，只点名给地址。

## 这册书写什么

上一册手造机制，这一册读穿实现。Book6 收束时留下三扇门，本册推开第一扇——主链路门：一条 HTTP 请求从进门（协议解析）到出门（流式返回），要在 vLLM V1 的源码里穿过十七个站、跨过两次进程边界、全程被二十一份子 config 组成的 VllmConfig 管着走。把十七站逐站拆开，V1 的全部主链路就自然铺开；全书沿这条请求生命周期推进——每章认领一段站段，每章开篇回答同一个问题——请求现在在哪。

阅读的对象是一座城：近百万行的大仓里，vllm/v1 十五个子包、约十七万行是城的核心，城外还有一座几乎同体量的姊妹城 vllm-ascend（vLLM 的昇腾 NPU 后端）。进城用「三层法」：先问它在哪（结构定位），再问它在动吗（运行时观察），最后问「我理解对了吗」（实验对拍）。Book6 里亲手造过的每个算法，在这里被点名到类——调度折中落到调度器（Scheduler）的决策循环、分页 KV 落到块池（BlockPool）、前缀缓存落到哈希链、图执行落到 ACLGraph——手造的直觉直接兑换成读码的地图。

大项目把自训的 DESIGN-207M 注册进 vllm-ascend：HF（Hugging Face）直载与外部注册双路线真跑，同权重跨路线逐字一致，串起引擎认模型的四道注册门。招牌读数贯穿全书：自动前缀缓存（APC）命中 56.0% 与手算天花板逐位咬合、ACLGraph 对 eager（逐算子执行）对拍 6.15×、启动 55.1 秒逐段拆账、eager 对 eager 23.1 ms 对照 mini 引擎的 59 ms——2.6× 的纯工程红利。

写作口径一句话：源码引用冻结在 v0.30.0（ced6857）阅读锚，实验观察落在 vllm 0.27.1 + vllm-ascend 运行栈（Atlas 910B3，全 NPU 主线）——「读穿」的操作性定义不是看完，而是两轨都对得上。十七站走完，主线之外横切的专题（投机深讲、结构化输出、PD 分离工程、可观测生态）交给 Book8。

## 为谁而写

两类读者。其一是沿书单走到第七册的本科生：已手造四版 mini 引擎、算过 roofline 与三本账，正好用亲手造过的机制当读码的索引。其二是工程背景较强、想真正读懂 V1 源码的推理工程师：可从第 2 章的地形图直入，遇 Book6 账本引用再回翻——样例路径是「ch02 地形图定位目标子包 → ch12 起服跟跑一条请求 → 按需回翻 Book6」；第一类读者的样例路径则是从 ch00 顺读，每章先对齐「请求现在在哪」再进源码。

硬前置是 Book6 全册——调度折中、分页 KV、批处理五部曲，以及 kernel、采样、投机、量化、图执行五个深化项；软前置是 Book3-5 的架构面（GQA、MoE 与 MLA、线性族），按回指使用，另需 PyTorch 与 Python 多进程基础。

体量 14 章，约一学期课程。实验件全部标 fast/full 档：fast 档一张空闲 Atlas 910B3 单卡分钟级可复现（起服 + 一请求），full 档扩到分位读数与参数扫描。动手三件准备：repos/ 下 vllm 与 vllm-ascend 两个浅克隆、source env.sh、一张空闲 NPU 卡。
