# 第 12 章 收束：满注意力不再是唯一解

## 12.0 从五册的模型演进回到整体

Transformer 给本系列提供了一个可持续改造的蓝本。预训练改变学习目标与使用方式，现代开源骨架改进归一化、门控、位置与 KV 共享，MoE 和 MLA 分别改变参数参与方式与历史表示。本册再把注意力拆成三个可以重新选择的问题：看哪些位置，精细读取哪些历史，用什么状态保存过去。

收束时不必记住全部型号，而应能面对一个新结构，指出它改了蓝本的哪里、解决哪项成本、保留了什么能力，以及证据尚未覆盖什么。本章回顾三条路线、两台教学模型、贯穿五册的知识关系，并将状态和计算问题接到后续推理系统。

## 12.1 三条路线：不同的成本，也有不同的信息限制

**窗口改变直接可见范围。**同一层只访问最近 $W$ 个位置，缓存可以封顶为 $\min(n,W)$，主注意力工作也随窗口受限。但掩码本身不会让稠密实现自动省下计算，需要相应内核和缓存策略。跨层传播可以扩大可达范围，却不保证信息已经学会传递；在全注意力预训练模型上直接裁窗，与从头训练原生窗口模型也不是同一干预。Gemma3、gpt-oss 保留部分全局层，因此整机缓存仍有随长度增长的项。

**稀疏改变读取集合。**NSA 按块组织，DSA 用索引器选 token，CSA 在压缩条目上选择，IndexShare 复用部分层的选择结果。被选集合上的 softmax 可以精确计算，但相对全历史的结果通常是近似的，误差与遗漏的注意力质量和对应值向量有关。索引器本身的工作不能从成本账里消失，DSA 的选择也不自动减少全部历史存储。GLM-5 的不同适配实验分属不同底座和表格，不构成稀疏路线普遍优于线性的证明。

**线性递推改变记忆形式。**线性核注意力把前缀和合并进矩阵与归一化向量；Delta rule 用预测残差修正关联记忆；GDN 先衰减再定向更新；KDA 进一步让各键通道有不同遗忘率。固定状态的大小与长度无关，但在有限精度、有限容量条件下无法无条件保存任意长历史的全部独立信息。它仍然可以在适当任务和键结构上精确召回，不能笼统说“固定状态不做检索”。混合模型保留显式历史通路，是对这些需求的一种回应，比例与层位置需要实验选择。

K3 的 69 个 KDA 层约占四分之三，而不是九成；24 个 MLA 层仍保留逐条历史。其约 0.75% 的数字比较的是指定 1M 长度下固定矩阵状态与主潜在 KV 的元素量，使用同字节宽度时才可直接换成字节比例，并未覆盖全部运行缓存。交叉点也只比较同一模型的两类存储项，不能推出速度或质量的“免费收益”。

因此选型要联合检查：任务要保留哪些细节、状态如何更新、每一步读取多少、实现怎样执行，以及训练和评测是否覆盖目标长度。低位宽压低每条记录的字节数，固定状态改变记录方式，两者不是同一种“存储不增长”。这些方案可以组合，也都仍有继续改进的空间。

## 12.2 我们的机器回望：两台机器与三代血统

判决之后看机器。本册单轨主线交付两台：第 6 章的 **K3 玩具**（toyA，总参 43,905,888、激活非嵌入 11,662,176，assert 双口径）与第 9 章选做的**三刀机**（409,000,736，枚举=手算=定版常数逐位一致）。玩具的血统写在 import 语句里：Book3 的 RMSNorm 与 RoPE、Book4 的 MLA 与 DeepSeekMoE、本册的 KDA——四代组件一台机器；它的两个正档读数值得带走：门粒度双臂在 800 步 loss 打平（5.491 对 5.500，预注册分支③命中——粒度的 loss 收益在玩具档不可分辨），但 $g$ 分布自己分了化，跨通道 std 从初始化的一点 $-2.5$ 拉开到深层 1.62——「每通道学出了不同的遗忘速度」从报告断言变成第一手实测；K3 化换装（per-channel 门+直接投影输出门）单点替换账 +372,048（44,277,936），逐项闭合。三刀机则以两刀机为底座：9 层注意力插槽换 GDN（层 7,393,312）、MLA 保留人读第 4/8/12 层（config 0 起 3/7/11，末层全局承 K3 惯例）、$w_{\text{expert}}$ 938→810 等总参补偿——冒烟初始 loss 10.5916 贴预言 10.5783，一窗 100 步整合短训 train 降至 7.4708、eval 7.3838，无 NaN（12.824 s/step 热漂移如实报，超窗 ckpt 续跑）。它的分类型状态账是三栏账本的教学版：MLA 3 层 960 元素/token 无界+GDN 9 层固定 1,317,888，交叉点 $n^*\approx1{,}373$。

## 12.4 从模型状态到推理系统

模型公式只规定每次输入和状态更新，服务系统还必须决定何时为哪条请求执行这些计算。全局 KV 保留逐条历史，窗口 KV 可以滚动淘汰，GDN/KDA 状态不断被更新；请求暂停、取消、复用前缀或验证投机 token 时，三者的生命周期并不相同。固定容量也不等于可以随意回滚，旧状态可能已经被覆盖。

阅读路线因此分为三个层次：[Book6](../book6-inference-systems-intro/README.md)先讨论推理的成本和方法；[Book7 的状态管理](../book7-vllm-v1-architecture/ch06-KV状态的管理与复用.md)与[模型硬件边界](../book7-vllm-v1-architecture/ch08-模型与硬件的适配边界.md)解释架构职责；[Book8 的混合状态](../book8-vllm-v1-source-code/ch25-混合模型的状态类型与恢复边界.md)、[投机验证](../book8-vllm-v1-source-code/ch20-投机解码的候选验证与状态修正.md)和[多模态特征](../book8-vllm-v1-source-code/ch22-多模态特征的位置调度与缓存.md)进一步进入对象和源码。它们不会假设所有状态都是同一种 KV。

本册三次改装模型提供了一个具体输入：总参数 409,000,736，主潜在 KV 为每 token 960 元素，GDN 固定状态合计 1,317,888 元素。系统可以据此估算资源，但真实容量还取决于批量、数据类型、内核工作区和状态保存策略。MoE 的专家通信、稀疏选择的索引成本、长图像前缀的预填充，也都需要实现层的验证。架构优化与系统优化会继续互相提出问题。

## 12.6 合上这本书之前

五册一直在做同一件事：保留能工作的蓝本，找出新任务与预算带来的限制，再逐项修改。真正可迁移的知识不是“哪一家用了哪个组件”，而是能说明改造位置、推理依据、信息代价与实验证据。

先看信息：哪些历史可被直接读取，哪些已经被压缩到状态？再看计算：矩阵和向量的形状是什么，哪些计算重复，哪些可以合并？最后看条件：等参数、等算力、相同数据与相同硬件是否真的成立，观察到了什么，尚不能断言什么？这三组问题能让公式、图和实验始终回到同一台模型上。

下一册继续使用这些状态和计算对象，讨论它们如何在推理系统中高效协作。
