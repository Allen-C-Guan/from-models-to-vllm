# 附录A　实践、验证与历史资产

正文需要的数学推导全部留在各章。本附录集中运行方式、实验边界和完整工程入口，跳过它不影响理解模型设计。

## A.1 数学练习与小型翻译实验

正式书仓中进入本册目录，使用已安装PyTorch的Python环境：

```bash
python code/verify_ch01.py
python code/verify_math.py
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 python code/train_toy.py --steps 400
```

工作区运行时先`source ./env.sh`，再执行`code/Book1-5-系统重写/book1/`下对应脚本。每次独立shell都重新激活。本册CPU实验不申请NPU，也不需要模型下载。PyTorch实际版本由输出JSON记录；没有自动安装或更换依赖。

[模型实现](code/model.py)采用原版残差后LN的组织；[数学验证](code/verify_math.py)检查解析梯度、独立实现等价与因果性；[小实验](code/train_toy.py)保存所有种子、数据划分、实际生成例子、损失曲线与交叉注意力权重。输出写入本册`log/examples/`，可按需要保存不同实验的结果。

训练脚本默认使用两条CPU计算线程；环境变量同时限制BLAS线程，避免小张量任务被过多线程调度拖慢。

数学验证结果见数学练习脚本的运行输出，小实验见训练脚本的运行输出。float64等价检验与float32学习实验分开。当前没有自然语言WMT复现、NPU性能或生产内核速度测试。

## A.2 从小实验扩展到自然语言翻译

完整工程至少需要以下互相衔接的步骤，不能只替换一个数据文件就默认评测可比。

先保存训练/验证/测试原文划分，再仅用训练集学习分词规则；将源目标符号编码为ID，明确BOS/EOS与padding策略。按长度分批降低填充，但确保RNN基线读取的最终状态对应实际句尾，而不是批量补零之后的假位置。使用packed sequence或按有效长度取状态，是避免“组批税”歪曲比较的重要检查。

训练循环记录有效token平均损失、优化步骤、学习率、梯度范数与验证NLL；checkpoint保留模型参数、词表、配置和随机种子。推理从BOS自回归开始，达到EOS或最大长度结束，再去分词、按固定BLEU签名评分。按句长分桶有助定位问题，但每桶样本量也要报告。

对照GRU固定摘要、GRU加注意力与Transformer时，首先明确比较的是同参数、同token预算、同训练时长还是同优化步数。它们不能同时被一句“公平比较”自动满足。吞吐还要控制批量形状、设备同步、预热和统计窗口，训练tokens/s与生成tokens/s不是同一指标。

长度外推实验应固定训练长度范围，再在更长输入上评测；区分“能运行”“损失可计算”“实际生成仍正确”。模型能够计算某个位置编码不等于任务能力外推已成功。

## A.4 怎样做有解释力的消融

先写出假设，再决定能隔离它的操作。例如删除源位置编码检验的是某种顺序信息入口；改变头数且同时保持总宽度，才接近比较多套读取；删除缩放还会改变分数/梯度尺度，可能需要报告优化设置是否仍相同。

用多个种子估计波动，完整记录全部运行，而不是只保留最好一个；少量种子的均值和标准差不是普遍显著性保证。若设计了很多消融并挑出最好结果，还存在选择偏差。小差异应结合重复性、数据量与实际意义解释。

本次第15章没有把三种子包装成稳定的跨任务结论；它将无位置结构的任务上界与数值观察对应，带位置模型的失败也原样保留。以后扩大实验应继承这种证据纪律，而非继承某个分数。
